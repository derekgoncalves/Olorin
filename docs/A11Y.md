# Acessibilidade

Meta (PROMPT seção 16): WCAG 2.2 nível AA, Lighthouse Acessibilidade 100 e zero violações no axe-core em todas as páginas.

## O que o site faz

| Recurso | Onde |
|---|---|
| Link "Pular para o conteúdo" (primeiro item ao apertar Tab) | `src/_includes/layouts/base.njk` |
| Um `<h1>` por página e títulos em ordem; marcos `header`, `nav` (com nome), `main`, `footer` | todos os templates (o build confere o `<h1>`) |
| Menu do celular como diálogo: foco vai para dentro, Tab circula só dentro, **Esc** fecha e o foco volta ao botão | `src/scripts/modulos/cabecalho.js` |
| Submenu de serviços abre por clique, teclado (Enter/Espaço) e fecha com **Esc** | idem |
| Formulário: rótulo visível em todo campo, erro ligado ao campo (`aria-describedby` + `aria-invalid`), resumo de erros anunciado (`aria-live`), foco no primeiro campo com erro e no título da etapa 2 | `src/_includes/components/formulario.njk`, `src/scripts/modulos/formulario.js` |
| Formulário funciona sem JavaScript (envio tradicional e página de erro legível) | `src/php/enviar.njk` |
| Botão **Pausar animações** nas faixas animadas e no rodapé (WCAG 2.2.2); a escolha fica salva | `src/scripts/modulos/interacoes.js`, `animacoes.css` |
| `prefers-reduced-motion`: sem animação, sem cursor-estrela, cursor do título pisca só 8 vezes no modo normal | `src/styles/animacoes.css` |
| Cursor-estrela nunca esconde o cursor do sistema e só existe com mouse | `src/scripts/modulos/cursor.js` |
| Gráfico do relatório tem tabela equivalente para leitor de tela | `src/_includes/secoes/relatorio.njk` |
| Calculadora sem JavaScript vira uma tabela com todos os valores | `src/_includes/components/ui.njk` |
| Perguntas frequentes com `<details>`/`<summary>` nativos | `ui.faqLista` |
| Cards de serviço inteiros clicáveis com um único link (sem link duplicado para leitor de tela) | `ui.cardServico` |
| Imagens informativas com descrição (`alt`); decorativas com `alt=""` | `src/assets/manifest.json` (o build barra imagem sem `alt`) |
| Links que abrem outra aba com `rel="noopener"` | o build confere |
| Fonte pixel nunca abaixo de 12 px e só em rótulos curtos | `docs/BRAND.md` |
| Alvos de toque com pelo menos 24 × 24 px (WCAG 2.5.8) | `botao.css`, `rodape.css`, `formulario.css` |

## Roteiro de teste manual com leitor de tela

Faça uma vez antes de publicar e depois de mudanças grandes. Leva uns 20 minutos.

**Windows + NVDA (gratuito, <https://www.nvaccess.org>) com Chrome ou Firefox**

1. Abra a home e aperte **Tab**: o primeiro item deve ser "Pular para o conteúdo". Aperte Enter: o foco vai para o conteúdo.
2. Aperte **H** várias vezes: os títulos devem ser lidos em ordem e fazer sentido sozinhos (um só título principal).
3. Aperte **D** (marcos): devem aparecer "banner", "navegação Principal", "principal" e "informações de conteúdo" (rodapé).
4. **Chegar a um serviço pelo menu:** com Tab, vá até "Serviços", abra a lista com Enter, escolha "Tráfego pago". Na página do serviço, a trilha "Você está em" deve ler Home › Serviços › Tráfego pago.
5. **Perguntas:** na seção Dúvidas, vá até uma pergunta e aperte Enter: o NVDA deve dizer "expandido" e ler a resposta.
6. **Enviar o formulário:**
   - Deixe tudo vazio e aperte "Continuar": o NVDA deve anunciar o erro e o foco ir para "Seu nome".
   - Preencha nome e um WhatsApp com DDD 20: deve anunciar que o DDD não existe.
   - Corrija e continue: o foco vai para o título "O que você precisa" (etapa 2).
   - Marque um serviço (as opções são lidas como caixas de seleção), escolha a faixa de investimento, marque o consentimento e envie: deve abrir a página de obrigado.
7. **Celular:** com o leitor de tela, abra o menu (botão "Abrir menu"): o foco deve ficar preso dentro do menu; Esc fecha.

**iPhone + VoiceOver (Ajustes → Acessibilidade → VoiceOver)**

1. Deslize para a direita para ir item a item pela home: o botão do menu deve ser lido como "Abrir menu, botão".
2. Use o **rotor** (girar dois dedos) em "Títulos" e navegue pelos títulos.
3. Abra uma pergunta frequente com toque duplo.
4. Faça o mesmo envio do formulário do passo 6 acima.
5. Confira que a barra fixa de baixo (WhatsApp / Orçamento) não cobre o botão de enviar.

**Mac + VoiceOver (Cmd+F5) com Safari:** repita os passos 1 a 6 do NVDA usando VO+U (rotor) para títulos, links e marcos.

Anote qualquer coisa lida de forma estranha (ex.: ícone lido como "imagem", botão sem nome) e abra uma tarefa.

## Resultados

Medição de 09/10/2026, no build final:

- **axe-core 4.14** (WCAG 2.0, 2.1 e 2.2, níveis A e AA): **nenhuma violação séria ou crítica** em `/`, `/servicos/`, `/servicos/trafego-pago/`, `/sobre/`, `/promo/`, `/obrigado/` e `/politica-de-privacidade/`, em 390 e 1280 px (`npm test`).
- **Lighthouse, Acessibilidade:** 100 em todas as páginas medidas (`docs/PERFORMANCE.md`).
- **Corrigidos na revisão:**
  - fonte pixel abaixo de 12 px (trilha, etiquetas, títulos de janela);
  - link do rodapé das campanhas sem sublinhado;
  - contraste do texto do Método sobre o símbolo decorativo;
  - acentos encostando na linha de cima dos títulos.
- **Pendente:** o roteiro manual com NVDA e VoiceOver acima precisa ser feito por uma pessoa, antes de publicar.
